# Mini NPU 시뮬레이터

## 1. 프로젝트 개요

Python으로 MAC(Multiply-Accumulate) 연산을 구현하여 십자가(Cross)와 X 패턴을 판별하는 콘솔 프로그램이다.

3×3부터 25×25까지의 2차원 배열을 처리하고, 패턴 크기에 따른 연산 횟수와 실행 시간을 분석한다.

NumPy 등의 외부 라이브러리를 사용하지 않고 Python 기본 기능만으로 구현하였다.

## 2. 프로젝트 파일 구성

- `main.py`: Mini NPU 시뮬레이터 실행 코드
- `data.json`: 크기별 필터와 테스트 패턴 데이터
- `README.md`: 프로젝트 설명 및 결과 리포트
- `.gitignore`: Git 추적 제외 파일 설정

## 3. 실행 방법

1. Python이 설치된 환경에서 프로젝트 폴더를 연다.
2. 터미널에서 `python3 main.py`를 실행한다.
3. 메뉴에서 원하는 모드를 선택한다.

**실행 메뉴**

- `1`: 사용자 입력 모드 (3×3)
- `2`: JSON 데이터 분석 모드
- `0`: 프로그램 종료

## 4. 주요 기능

### 사용자 입력 모드

- 필터 A, B와 패턴을 3×3 배열로 입력
- 행·열 개수와 숫자 입력 오류 검증
- 입력된 필터 저장 내용 출력
- MAC 점수 및 연산 시간 계산
- A/B/UNDECIDED 판정
- 3×3 성능 분석 출력

### JSON 데이터 분석 모드

- `data.json`에서 필터와 패턴 불러오기
- 5×5, 13×13, 25×25 배열 처리
- 패턴 크기에 맞는 필터 자동 선택
- 필터 및 패턴 크기와 데이터 형식 검증
- 라벨 정규화 및 MAC 점수 계산
- expected와 비교하여 PASS/FAIL 판정
- 전체 테스트 결과와 실패 사유 출력

### 성능 분석

- 각 크기별 MAC 연산 10회 반복 측정
- 평균 연산 시간(ms) 계산
- 연산 횟수(N²) 출력
- 파일 읽기와 콘솔 출력 시간을 측정 구간에서 제외

## 5. 판정 기준

두 필터의 MAC 점수를 비교하여 높은 점수를 얻은 필터를 선택한다.

실수 계산의 오차를 고려하여 epsilon을 `1e-9`로 설정하였다.

`abs(score_a - score_b) < 1e-9`이면 동점으로 판단하고 `UNDECIDED`를 반환한다.


JSON 분석에서는 `+`와 `cross`를 `Cross`로, `x`를 `X`로 정규화하여 비교한다.

### 5.1 라벨 정규화 함수의 모듈화

`normalize_label()`은 다양한 라벨을 표준 라벨(Cross/X)로 변환하는 함수이다.

- 유지보수: 라벨 변환 규칙을 한 곳에서 관리하여 수정이 편리하다.
- 재사용성: 여러 기능에서 동일한 정규화 함수를 사용할 수 있다.
- 확장성: 새로운 라벨이 추가되면 정규화 규칙을 쉽게 확장할 수 있다.
- 일관성: 입력된 라벨의 표기가 달라도 동일한 기준으로 비교할 수 있다.

라벨 정규화를 별도 함수로 분리하면 중복 코드를 줄이고 프로그램의 유지보수성과 확장성을 높일 수 있다.
### 5.2 모드별 동점 판정 규칙

사용자 입력 모드와 JSON 분석 모드는 동일한 epsilon(1e-9) 기준을 사용하지만, 판정 결과를 출력하는 방식이 다르다.

- **사용자 입력 모드:** 필터 A와 B의 점수를 비교하여 A 또는 B로 판정하며, 동점일 경우 '판정 불가'로 표시한다.
- **JSON 분석 모드:** Cross와 X 필터의 점수를 비교하여 Cross 또는 X로 판정하며, 동점일 경우 'UNDECIDED'로 표시한다.
- **동점 조건:** 두 모드 모두 `abs(score_a - score_b) < 1e-9`이면 동점으로 처리한다.
- **정답 비교:** 사용자 입력 모드는 정답 데이터가 없어 PASS/FAIL을 계산하지 않는다. JSON 분석 모드는 expected와 비교하며, UNDECIDED가 발생하면 Cross/X 정답과 불일치하여 FAIL로 처리한다.

두 모드 모두 내부적으로 동일한 `decide_result()` 함수를 사용한다. 따라서 계산 기준은 일관되게 유지하면서 모드의 목적에 맞는 결과를 출력할 수 있다.
### 5.3 새로운 라벨 확장 절차

현재 프로그램은 Cross와 X 두 가지 패턴을 판정하도록 구현되어 있다. 새로운 패턴을 추가하려면 다음 순서로 기능을 확장해야 한다.

1. **라벨 정의:** 새로운 패턴의 표준 라벨을 정한다. 예를 들어 Triangle을 추가한다.
2. **정규화 함수 수정:** `normalize_label()`에 새로운 라벨과 허용할 입력 표기를 추가하여 Triangle로 변환하도록 한다.
3. **필터 추가:** `data.json`의 각 `size_N` 필터 그룹에 Triangle 필터를 추가한다.
4. **판정 로직 확장:** 기존 `decide_result()`는 두 점수만 비교하므로, 세 개 이상의 필터 점수를 비교해 가장 높은 점수의 라벨을 선택하도록 수정한다. epsilon을 이용한 동점 처리도 유지한다.
5. **출력 기능 수정:** JSON 분석 결과에 Triangle의 MAC 점수와 판정 결과가 출력되도록 수정한다.
6. **테스트 데이터 추가:** `data.json`에 Triangle 패턴과 `expected` 값을 추가하고 PASS/FAIL을 검증한다.
7. **패턴 생성기 확장:** 자동 생성 기능까지 지원하려면 `generate_pattern()`에도 Triangle 생성 규칙을 추가한다.

라벨 정규화 기능을 별도 함수로 분리했기 때문에 새로운 라벨의 표기 규칙을 한 곳에서 관리할 수 있다. 다만 현재 프로그램은 두 필터 비교를 전제로 하므로, 새로운 패턴을 실제로 지원하려면 판정 및 출력 기능도 함께 확장해야 한다.
### 5.4 대규모 데이터 처리 및 최적화

현재 프로그램은 최대 25×25 배열을 처리하지만, 1000×1000 배열로 확장하면 연산 시간과 메모리 사용량이 크게 증가한다.

**1. 연산 시간 문제**
- 1000×1000 배열은 필터 하나당 1,000,000회의 MAC 연산이 필요하다.
- Cross와 X 두 필터를 계산하면 총 2,000,000회의 MAC 연산을 수행한다.
- 배열 크기에 따라 연산량이 N²으로 증가하므로 시간 복잡도는 O(N²)이다.
- Python의 이중 반복문으로 처리할 경우 배열이 커질수록 실행 시간이 증가한다.

**2. 메모리 사용량 문제**
- 1000×1000 배열에는 1,000,000개의 숫자가 저장된다.
- 숫자 하나를 8바이트 실수로 저장한다고 가정하면 배열 하나의 데이터 용량은 약 8MB이다.
- 실제 Python 리스트에서는 객체와 리스트 구조에 따른 추가 메모리가 필요하다.
- 여러 패턴과 필터를 동시에 저장하면 메모리 사용량이 더욱 증가한다.

**3. 우선 적용할 최적화 방법**
1. 불필요한 배열 복사를 줄여 추가 메모리 사용을 최소화한다.
2. 블록(Block) 단위로 데이터를 나누어 연산하는 방식을 적용한다.
3. 큰 데이터를 한꺼번에 메모리에 올리지 않고 필요한 블록만 순차적으로 읽어 처리한다.
4. 2차원 배열과 1차원 배열의 메모리 접근 방식 및 실행 시간을 비교한다.
5. 반복적인 인덱스 접근과 불필요한 연산을 줄여 처리 속도를 개선한다.

블록 처리로 메모리 사용량을 줄이려면 데이터 로드 과정도 블록 단위로 변경해야 한다. 전체 JSON을 먼저 읽은 상태에서는 단순히 계산만 나누어 수행해도 메모리 절감 효과가 제한적이다.

**4. 최적화 방향**

우선 불필요한 메모리 사용을 줄이고 블록 단위 처리 방식을 검토한다. 이후 동일한 입력 데이터를 이용하여 최적화 전후의 평균 실행 시간과 메모리 사용량을 비교한다.

단, 블록 처리나 1차원 배열 변환만으로 MAC 연산 횟수 자체가 줄어드는 것은 아니므로 시간 복잡도는 O(N²)로 유지된다.
### 5.5 CPU와 NPU의 연산 방식 및 병목 분석

**1. CPU와 NPU의 차이**

- CPU(Central Processing Unit)는 다양한 명령어와 복잡한 프로그램 제어를 처리하는 범용 프로세서이다.
- NPU(Neural Processing Unit)는 AI 모델에서 반복적으로 수행하는 행렬 연산과 MAC 연산을 효율적으로 처리하도록 설계된 전용 프로세서이다.
- CPU도 병렬 처리가 가능하지만, NPU는 대량의 단순 곱셈·누적 연산을 병렬로 실행하는 데 특화되어 있다.
- 따라서 대규모 AI 연산에서는 NPU가 CPU보다 높은 처리 효율을 제공할 수 있다.

**2. 대규모 MAC 연산의 병목 현상**

1. **직렬 처리 병목:** Python 이중 반복문으로 MAC 연산을 순차 실행하면 배열 크기가 커질수록 계산 시간이 증가한다.
2. **메모리 접근 병목:** 배열의 각 원소를 반복적으로 읽어야 하므로 데이터 접근에 시간이 소요된다.
3. **메모리 대역폭 병목:** 프로세서의 계산 속도가 빨라도 메모리에서 데이터를 충분히 빠르게 공급하지 못하면 성능이 제한된다.
4. **데이터 전송 병목:** NPU를 사용할 때도 데이터를 장치로 전달하는 과정에서 추가 시간이 발생할 수 있다.

**3. CPU와 NPU의 권장 작업 배치**

- **CPU:** 사용자 입력, JSON 파일 읽기, 데이터 검증, 프로그램 제어 등 범용 작업에 사용한다.
- **NPU:** 대규모 행렬 곱셈, 반복적인 MAC 연산 등 병렬 계산이 많은 작업에 활용한다.
- 작은 배열에서는 데이터 전송 및 실행 준비 비용 때문에 CPU가 더 효율적일 수 있다.
- 큰 배열에서는 연산량과 데이터 재사용률을 고려하여 NPU의 병렬 처리 기능을 활용하는 것이 유리할 수 있다.

**4. Mini NPU 시뮬레이터 분석**

현재 프로그램은 실제 NPU 하드웨어를 사용하지 않고 Python 반복문으로 MAC 연산을 구현한 시뮬레이터이다.

1000×1000 배열은 필터 하나당 1,000,000회의 MAC 연산이 필요하며, 두 필터를 처리하면 총 2,000,000회의 MAC 연산을 수행한다.

현재 구현에서는 배열 크기가 증가할수록 반복문 실행과 메모리 접근이 주요 성능 부담이 될 수 있다.

실제 NPU 환경에서는 병렬 MAC 연산을 통해 처리 시간을 단축할 수 있지만, 메모리 대역폭과 데이터 전송 비용 역시 고려해야 한다.

따라서 작은 데이터와 프로그램 제어는 CPU에 배치하고, 대규모 반복 연산은 NPU에 배치하는 방향이 효율적이다. 단, 실제 성능 차이는 하드웨어와 실행 환경에 따라 측정해야 한다.

### 6.2 실패 원인 분석 및 시간 복잡도 분석

1. 전체 6개 테스트 중 3개가 PASS, 3개가 FAIL로 판정되었다.
2. `size_5_1`은 Cross와 X의 MAC 점수가 모두 0.9로 계산되어 동점이 발생하였다.
3. `size_13_2`는 두 필터 점수가 모두 7.5로 계산되어 UNDECIDED가 발생하였다.
4. `size_25_1`은 두 필터 점수가 모두 4.9로 계산되어 UNDECIDED가 발생하였다.
5. 세 케이스 모두 expected는 Cross 또는 X이므로 UNDECIDED와 일치하지 않아 FAIL 처리되었다.
6. 이러한 실패는 프로그램이 비정상 종료된 것이 아니라 정해진 비교 정책에 따른 판정 결과이다.
7. 부동소수점 계산에서 발생할 수 있는 미세한 오차를 처리하기 위해 epsilon을 적용하였다.
8. epsilon보다 작은 점수 차이는 동점으로 처리하여 판정의 일관성을 유지하였다.
9. expected와 필터 키의 라벨을 표준화하여 `+`, `cross`, `x` 표기 차이로 인한 비교 오류를 방지하였다.
10. JSON 스키마나 배열 크기가 잘못된 경우 해당 케이스를 FAIL로 기록하도록 구현하였다.
11. MAC 연산은 이중 반복문으로 N×N 배열의 모든 원소를 한 번씩 처리한다.
12. 따라서 한 번의 MAC 연산에 필요한 곱셈 횟수는 N²이고 시간 복잡도는 O(N²)이다.
13. 3×3은 9회, 5×5는 25회, 13×13은 169회, 25×25는 625회의 곱셈을 수행한다.
14. 두 필터를 비교하면 MAC 연산을 두 번 수행하지만 시간 복잡도는 여전히 O(N²)이다.
15. 각 크기별 연산을 10회 반복 측정하여 평균 실행 시간을 계산하였다.
16. 배열 크기가 증가하면 연산 횟수도 증가하지만 실제 측정 시간은 실행 환경에 따라 차이가 발생할 수 있다.
17. MAC 점수 계산에서 추가로 사용하는 누적 변수의 공간 복잡도는 O(1)이며, 입력 배열 자체의 저장 공간은 O(N²)이다.
18. 최종적으로 모든 테스트를 실행하고, 성공·실패 여부와 실패 원인을 확인할 수 있도록 구현하였다.

## 7. 최종 결과

Mini NPU 시뮬레이터를 통해 2차원 배열을 이용한 MAC 연산과 패턴 판정 원리를 구현하였다.

사용자 입력 및 JSON 분석, 라벨 정규화, epsilon 기반 비교, 성능 측정, 오류 처리와 결과 리포트 기능을 구성하였다.

이를 통해 입력 데이터 크기에 따른 연산량의 변화와 패턴 판정 과정에서 발생할 수 있는 문제를 분석하였다.
## 8. 보너스 과제

### 8.1 메모리 접근 최적화

- 기존의 2차원 배열을 길이 N²의 1차원 배열로 변환하였다.
- 동일한 패턴과 필터를 사용하여 2D와 1D MAC 연산 결과를 비교하였다.
- 두 방식 모두 10회 반복 측정하여 평균 실행 시간을 계산하였다.
- 공정한 MAC 함수 실행 시간 비교를 위해 배열 변환 시간은 제외하였다.
- 두 방식의 점수가 epsilon 허용오차 내에서 일치하는지 검증하였다.
- 1차원 배열이 항상 더 빠르지는 않으며, 실제 실행 환경에 따라 성능이 달라질 수 있다.

### 8.2 패턴 자동 생성기

- 크기 N을 입력하면 N×N 십자가(Cross)와 X 패턴을 자동 생성한다.
- 3×3부터 25×25까지의 크기를 지원한다.
- 생성된 3×3 패턴은 사용자 입력 모드에서 재사용할 수 있다.
- 생성된 패턴은 MAC 성능 분석에도 활용할 수 있다.
