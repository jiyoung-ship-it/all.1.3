# Mini NPU 시뮬레이터

## 1. 프로젝트 개요

Python으로 MAC(Multiply-Accumulate) 연산을 구현하여 십자가(Cross)와 X 패턴을 판별하는 콘솔 프로그램이다.

3×3부터 25×25까지의 2차원 배열을 처리하고, 패턴 크기에 따른 연산 횟수와 실행 시간을 분석한다.

NumPy 등의 외부 라이브러리를 사용하지 않고 Python 기본 기능만으로 구현하였다.

## 2. 프로젝트 파일 구성

- `main.py`: Mini NPU 시뮬레이터 실행 코드
- `data.json`: 크기별 필터와 테스트 패턴 데이터
- `README.md`: 프로젝트 설명 및 결과 리포트
- `.gitignore`: Git 추적 제외 파일 설정

## 3. 실행 방법

1. Python이 설치된 환경에서 프로젝트 폴더를 연다.
2. 터미널에서 `python3 main.py`를 실행한다.
3. 메뉴에서 원하는 모드를 선택한다.

**실행 메뉴**

- `1`: 사용자 입력 모드 (3×3)
- `2`: JSON 데이터 분석 모드
- `0`: 프로그램 종료

## 4. 주요 기능

### 사용자 입력 모드

- 필터 A, B와 패턴을 3×3 배열로 입력
- 행·열 개수와 숫자 입력 오류 검증
- 입력된 필터 저장 내용 출력
- MAC 점수 및 연산 시간 계산
- A/B/UNDECIDED 판정
- 3×3 성능 분석 출력

### JSON 데이터 분석 모드

- `data.json`에서 필터와 패턴 불러오기
- 5×5, 13×13, 25×25 배열 처리
- 패턴 크기에 맞는 필터 자동 선택
- 필터 및 패턴 크기와 데이터 형식 검증
- 라벨 정규화 및 MAC 점수 계산
- expected와 비교하여 PASS/FAIL 판정
- 전체 테스트 결과와 실패 사유 출력

### 성능 분석

- 각 크기별 MAC 연산 10회 반복 측정
- 평균 연산 시간(ms) 계산
- 연산 횟수(N²) 출력
- 파일 읽기와 콘솔 출력 시간을 측정 구간에서 제외

## 5. 판정 기준

두 필터의 MAC 점수를 비교하여 높은 점수를 얻은 필터를 선택한다.

실수 계산의 오차를 고려하여 epsilon을 `1e-9`로 설정하였다.

`abs(score_a - score_b) < 1e-9`이면 동점으로 판단하고 `UNDECIDED`를 반환한다.

JSON 분석에서는 `+`와 `cross`를 `Cross`로, `x`를 `X`로 정규화하여 비교한다.

## 6. 결과 리포트

### 6.1 테스트 결과

제공된 `data.json`을 기준으로 다음 결과를 확인하였다.

| 항목 | 결과 |
|---|---|
| 전체 테스트 | 6개 |
| PASS | 3개 |
| FAIL | 3개 |

**케이스별 결과**

| 케이스 | expected | 판정 | 결과 |
|---|---|---|---|
| size_5_1 | X | UNDECIDED | FAIL |
| size_5_2 | Cross | Cross | PASS |
| size_13_1 | X | X | PASS |
| size_13_2 | Cross | UNDECIDED | FAIL |
| size_25_1 | X | UNDECIDED | FAIL |
| size_25_2 | Cross | Cross | PASS |

### 6.2 실패 원인 분석 및 시간 복잡도 분석

1. 전체 6개 테스트 중 3개가 PASS, 3개가 FAIL로 판정되었다.
2. `size_5_1`은 Cross와 X의 MAC 점수가 모두 0.9로 계산되어 동점이 발생하였다.
3. `size_13_2`는 두 필터 점수가 모두 7.5로 계산되어 UNDECIDED가 발생하였다.
4. `size_25_1`은 두 필터 점수가 모두 4.9로 계산되어 UNDECIDED가 발생하였다.
5. 세 케이스 모두 expected는 Cross 또는 X이므로 UNDECIDED와 일치하지 않아 FAIL 처리되었다.
6. 이러한 실패는 프로그램이 비정상 종료된 것이 아니라 정해진 비교 정책에 따른 판정 결과이다.
7. 부동소수점 계산에서 발생할 수 있는 미세한 오차를 처리하기 위해 epsilon을 적용하였다.
8. epsilon보다 작은 점수 차이는 동점으로 처리하여 판정의 일관성을 유지하였다.
9. expected와 필터 키의 라벨을 표준화하여 `+`, `cross`, `x` 표기 차이로 인한 비교 오류를 방지하였다.
10. JSON 스키마나 배열 크기가 잘못된 경우 해당 케이스를 FAIL로 기록하도록 구현하였다.
11. MAC 연산은 이중 반복문으로 N×N 배열의 모든 원소를 한 번씩 처리한다.
12. 따라서 한 번의 MAC 연산에 필요한 곱셈 횟수는 N²이고 시간 복잡도는 O(N²)이다.
13. 3×3은 9회, 5×5는 25회, 13×13은 169회, 25×25는 625회의 곱셈을 수행한다.
14. 두 필터를 비교하면 MAC 연산을 두 번 수행하지만 시간 복잡도는 여전히 O(N²)이다.
15. 각 크기별 연산을 10회 반복 측정하여 평균 실행 시간을 계산하였다.
16. 배열 크기가 증가하면 연산 횟수도 증가하지만 실제 측정 시간은 실행 환경에 따라 차이가 발생할 수 있다.
17. MAC 점수 계산에서 추가로 사용하는 누적 변수의 공간 복잡도는 O(1)이며, 입력 배열 자체의 저장 공간은 O(N²)이다.
18. 최종적으로 모든 테스트를 실행하고, 성공·실패 여부와 실패 원인을 확인할 수 있도록 구현하였다.

## 7. 최종 결과

Mini NPU 시뮬레이터를 통해 2차원 배열을 이용한 MAC 연산과 패턴 판정 원리를 구현하였다.

사용자 입력 및 JSON 분석, 라벨 정규화, epsilon 기반 비교, 성능 측정, 오류 처리와 결과 리포트 기능을 구성하였다.

이를 통해 입력 데이터 크기에 따른 연산량의 변화와 패턴 판정 과정에서 발생할 수 있는 문제를 분석하였다.
## 8. 보너스 과제

### 8.1 메모리 접근 최적화

- 기존의 2차원 배열을 길이 N²의 1차원 배열로 변환하였다.
- 동일한 패턴과 필터를 사용하여 2D와 1D MAC 연산 결과를 비교하였다.
- 두 방식 모두 10회 반복 측정하여 평균 실행 시간을 계산하였다.
- 공정한 MAC 함수 실행 시간 비교를 위해 배열 변환 시간은 제외하였다.
- 두 방식의 점수가 epsilon 허용오차 내에서 일치하는지 검증하였다.
- 1차원 배열이 항상 더 빠르지는 않으며, 실제 실행 환경에 따라 성능이 달라질 수 있다.

### 8.2 패턴 자동 생성기

- 크기 N을 입력하면 N×N 십자가(Cross)와 X 패턴을 자동 생성한다.
- 3×3부터 25×25까지의 크기를 지원한다.
- 생성된 3×3 패턴은 사용자 입력 모드에서 재사용할 수 있다.
- 생성된 패턴은 MAC 성능 분석에도 활용할 수 있다.
